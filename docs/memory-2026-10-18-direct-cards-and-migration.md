# 旧记忆完整迁移与记忆卡片首页

本轮依据用户最新要求，替换分类入口大卡片，移除首页的“检索设置与状态”“整理与旧资料”。不提交、不推送，不操作用户浏览器 Profile，不修改原备份。

## 修正的业务路径

确认迁移 → `completeMemoryMigration` → 原始快照及基础迁移 → 全部现存角色/关系范围 → 分批原子整理、价值判断、人设/世界书重复核对及语义关联 → 新条目与分类标签即时刷新。

- 基础保存完成不能再作为分类迁移完成的依据。界面展示完整流程的状态，失败保留原文及进度；重新进入可继续迁移。
- 一次确认持续处理全部批次，迁移不被日常自动整理的每日两批额度卡住。完成后恢复日常额度。
- 明确的整段无价值判断有独立 `discards` 协议，必须完整引用、解释原因且置信度足够；空回答不能冒充成功丢弃。
- 已存线下记忆的整理属于档案转换，不能要求重新提交一次新剧情同步授权。仍保留原来源、关系和事实权威；新线下写入的授权规则不变。
- 整理后文字的价值判断与原始聊天引用分开，保留原始引用。重新分类改变类型/时间后按最终修订记录处理进度，避免反复处理及游标卡在末尾。
- 一组失败时尝试其他组；连续三组失败停止，避免接口故障时反复付费。主动重试允许恢复失败批次；不伪报全部完成。
- 无法可靠判断的旧内容可作为带“待核实，暂不用于回忆”提示的卡片查看。原始父记录和已拆出的子记录不平铺重复，已跳过或撤回的内容不复活。

## 首页与去重

首页直接列出记忆卡片；上方保留紧凑筛选标签。共同经历、未来计划、对我的认知、TA的变化、TA的生活、线下经历显示为卡片角落标签。

使用已有的同范围文本归并，以及有引用和修订校验的高置信度语义重复关联进行展示聚合。不同关系、已变化的来源、仅“同一属性”的记录不能当作重复。全部存储原记录保留，合并的相关记录可在详情查阅。交流摘要留在相关背景的展开内容，不与其包含的条目默认平铺。

合并卡片的暂停/恢复、核心标记、编辑、撤回、忘记作用于相关副本，重新读取最新记录校验分组，不覆盖后台新写入。忘记时同时修正不同来源父记录，保留其他有效分句及其追溯关系。暂停不删除仍有效的语义关联，因此可以完整恢复；跨关系条目不在操作范围内。

2. `memoryMigrationExistingSource20261018.test.ts`：旧线下条目转换、原始引用保持、新剧情写入仍需授权、语义重复展示聚合、跨关系与来源变更保护。
3. 全量备份副本的浏览器流程验收：224 条原来源均保留，14 个关系范围完成业务流程；首页有记忆卡片，角落分类标签可见，两个技术区块及分类大卡片入口不再出现。**使用模拟模型判断，只证明完整流程与界面，不证明模型对224条内容的语义判断都正确。**
4. 真实模型抽样：从备份中实际抽取2条可用来源，完成2个范围、6次真实请求，生成4条存储记录，其中2条可展示并准入、1条跳过；两条原来源保留，未遗留待核实条目。使用用户提供的测试模型，未修改用户浏览器或原备份。**这不是全量224条真实模型验收。**
5. 手机、桌面、短高度视口的弹窗验证：内容自适应高度并居中；“稍后处理”不触发迁移或模型请求。
6. `memoryGroupedCardLifecycle20261018.test.ts` 与合成数据浏览器操作验收：全部相关副本一起暂停/恢复、加/取消核心、修订、撤回、忘记；独立关系保留。两个来源父记录中的其他分句仍有效，避免删除一件事连带使其余条目失效。

验收记录位于工作区外层 outputs；公开记录只含数量、状态及检查结果，不含用户记忆正文、API Key 或完整模型输入输出。原备份的 SHA-256 校验保持一致。
