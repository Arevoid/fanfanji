# 日程应用运行时约定

## 目标

日程应用将经期、见面约定、角色日程和用户日程汇聚到同一个入口，但每类记录仍由自己的领域模型负责。界面只消费日历投影，不直接拼接或写入其他应用的存储。

## 身份与关系范围

- 用户日程和经期记录只接受 `userIdentityId`，不同身份不得互相显示。
- 角色日程必须同时携带 `relationId`、`characterId` 和 `userIdentityId`；读取时必须三者精确匹配。
- 见面约定继续以 `Appointment` 为事实源，日历里的 `CalendarViewItem` 只是只读投影。
- 角色手机中的日程是角色日程的一个展示面。角色手机本地手动新增的记录仍保存在手机记录中，不覆盖主日程事实。

## AI 生成与确认

角色日程的一键生成是建议流程：调用统一 API 请求台账，使用 `schedule_generate` 目的，并携带人设、可见世界书和同一关系的近期上下文标签。模型返回的记录写入 `reviewState: "suggested"`、`source: "ai_generated"`，不能直接改写已确认的见面约定，也不能扩散到其他身份或关系。

没有真实 API 调用就不创建调用详情；估算值不能冒充服务商真实用量。

## 聊天上下文

线上聊天只读取当前关系范围内的角色日程。提示词适配器会去除存储 ID，仅展示标题、时间、状态和“AI 建议”标记；日程仅作为行为参考，不是强制动作，也不能让角色获知其他关系的安排。

## 删除、备份与迁移

“日程”数据删除范围包括旧版见面约定、角色日程、用户日程和经期记录。新增存储使用版本化键并保留旧数据；导入导出应通过现有系统备份流程处理，不得引入新的存储引擎。
