# 保存时并发保护

不再选举长期页面写入者，不续期，不因后台、休眠、计时器延迟或时间跳变将页面设为只读。
所有正常打开的页面都可以尝试保存。真实存储不可用仍应明确报错。

## 事务边界

- 记忆内容：同一 IndexedDB 读写事务内，对比当前数据集与本页已确认的快照，再写入变化记录。
  多数据集保存中任何一个发生冲突，整批回滚；不推进本次持久化成功状态。
- 聊天消息、线下条目与旧线下库：在既有数据事务中读取并校验已加载的存储快照。
  同页成功提交后才更新基线。无关的后台读取不能替旧界面授权覆盖。
- 阅读元数据（含兼容聊天快照）：按逻辑 key 比较并保存，不用其他 key 的读取更新其基线。
- 仍在 LocalStorage 的受保护数据：使用短 IndexedDB 事务串行执行比较与同步写入。
  返回 pending + durable 回执；调用者需要 await durable 才能确认保存。协调库不保存用户正文或凭据。
- 老数据首次转存：复制、读取校验及发布切换标记位于同一 IndexedDB 事务。
  第二个开启迁移的页面不得覆盖已经发布的新库；原数据在验证成功前保留。

## 冲突处理

不合并两个窗口对同一内容的矛盾修改，不自动重放旧快照，也不自动调用模型。
本次保存失败并提示保留输入、刷新后重试；不锁住整个应用。
当前聊天/线下采用存储快照级比较，因此不同记录的并发修改也可能保守地拒绝一次保存。
这比字段级合并严格，但不会静默覆盖已提交的新数据。

memoryWriterLease.ts 仅保留旧协议测试；新启动流程不获取或续期旧租约。
未刷新的旧版本页面不具备新的保存协议，更新后应刷新旧页面。

本保护不承诺跨多个独立数据库的分布式原子事务，既有来源关联及恢复协议仍负责跨库操作。
