# 阅读应用布局改版：第 5 轮（共读主页与房间阅读）

## 本轮目标

“共读”底部导航不再只是入口集合，而是当前用户与各 AI 好友的独立活动主页。同一本书与不同好友共读时，必须展示为不同卡片，并进入各自房间上下文。

## 页面结构

- 顶部显示正在进行的活动数量和隔离说明。
- 普通共读卡片展示书籍封面、好友头像、用户进度、AI 好友进度和最近更新时间。
- 穿书或自建世界活动继续显示“穿书”角标，并进入统一文游页面。
- 普通共读提供“继续共读”和“书房”两个明确入口。

## 操作规则

点击“继续共读”进入正常阅读器，不另造一套正文页面。阅读器接收精确 `ReadingRoom`：

- 页头显示当前共读好友。
- 段落评论角标只统计当前房间。
- “段评”写入当前 `readingRoomId + relationId + characterId`。
- “召唤”冻结用户选中的正文快照，并创建当前房间的讨论线程。
- 书签、高亮和私人笔记仍属于用户自己的阅读空间。

## 隔离边界

共读身份键保持为：

`userIdentityId + bookId + relationId + characterId + readingRoomId`

因此同一本书与好友 A、好友 B 建立的进度、评论、讨论和 AI 已知范围不会互相读取。页面跳转必须传房间 ID，不能只传书籍 ID 后再猜测好友。

## 记忆规则

阅读器中的评论和召唤首先保存在共读空间。只有用户看见并明确确认的讨论事实，才允许进入对应关系记忆；AI 未展示的后台内容不会进入主记忆。
