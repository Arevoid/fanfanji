# 阅读应用第 17 轮：穿书生成可靠性

## 目标

穿书回合生成可能经历模型返回格式错误、网络重试、多个页面同时打开或本地存储失败。本轮确保这些情况不会产生重复回合、错误分支或半保存状态。

## 请求幂等

每次用户点击“提交行动”都会生成一个 `requestId`，并随回合保存。再次使用同一个 `requestId` 时：

- 直接返回已经保存的回合；
- 不再次调用模型；
- 不增加新的正文、选项或状态变化。

这样可以覆盖请求超时后客户端重试、重复点击和页面恢复等情况。

## 生成重试边界

模型调用最多尝试两次。第一次返回无法解析或无法通过结构校验的内容时，第二次请求会明确要求只返回协议 JSON。

以下错误不会重试：

- 故事状态冲突；
- 故事不存在；
- 本地存储写入失败。

这些错误需要交给页面提示用户刷新或稍后重试，避免在旧状态上继续生成另一条分支。

## 状态冲突

生成开始时记录 `story.updatedAt`。提交时再次读取当前故事：如果期间已经被其他页面或设备写入，提交会返回 `conflict`，本次生成结果不会写入。

## 原子提交

回合和由回合推导出的故事状态会合并到同一个 `ReadingStoryStore` JSON 中，一次写入。底层存储适配器负责写后校验和恢复旧值，因此不会出现“回合已保存但章节、地点或情报没有更新”的半提交。

## 测试覆盖

`readingStoryReliability.test.ts` 覆盖：

1. 无效 JSON 重试后成功提交；
2. 相同请求 ID 的幂等返回；
3. 并发旧状态冲突拦截；
4. 存储写入失败后的原子回滚。
