# 小组件应用：产品与技术说明

## 目标

“小组件”是一个独立应用：用户可以用自然语言多轮描述桌面小组件，顶部实时预览，确认后保存、放置到桌面，或导出给其他人导入。制作人通过对话指定（例如“制作人是小明”），不再需要单独表单；导入后仍保留来源信息。

应用页采用按 `1x1`、`2x2`、`1x4`、`2x3`、`2x4` 尺寸直接排布的网格，不使用传统卡片列表。页面同时展示系统内置组件和用户自制组件；自制组件支持导出、导入和删除。

## 数据与持久化

- 规范化后的记录存放在独立 IndexedDB 数据库 `FanfanjiCustomWidgetsDB` 的 `widgets` object store 中。
- 每条记录使用 `schemaVersion: 1`，并由 `normalizeCustomWidget` 做白名单校验和长度限制。
- IndexedDB 不可用时，仓库自动回退到 `localStorage` 的 `phone_custom_widgets` 键；保存、删除和清空都会发出 `fanfanji:custom-widgets-changed` 事件。
- 系统备份把 IndexedDB 记录作为 `custom-widgets-v1` 一并导出和恢复；设置中的用户数据清理也提供单独的“小组件”选项。
- 桌面只保存小组件 ID 和尺寸/位置，渲染时从仓库读取完整定义。删除小组件后，原桌面挂载不会误删其他桌面项目；若挂载记录是历史孤儿 ID，渲染器会临时显示最近更新的定义，避免桌面出现空白，之后重新放置即可修复绑定。

## 生成边界

有可用模型配置时，应用要求模型只返回受限 JSON（文本、日历、清单、引用四类 block），不允许返回脚本、HTML 或外部请求。返回内容仍会经过本地 schema 校验。没有 API 或模型返回无效时，使用本地启发式草稿，保证应用可用且不会执行任意代码。

输入框下方以聊天形式保留多轮上下文；输入变化会先更新本地预览，发送后再请求模型。输入框旁的图片按钮可附加参考图，图片只随当前轮请求发送。模型只按世界观/用户描述修改明确要求的字段。

自制组件的主题透明度由组件自身（`paper`、`glass`、`midnight`、`sunrise`）决定，不读取设置中的全局小组件透明度；圆角设置仍可统一应用。

## 导入与导出

导出文件为 JSON（扩展名 `.ffwidget.json`）。页面右上角的“导出”会将当前已保存的小组件放入 `widgets` 数组，单个组件的快捷导出则保留 `widget` 字段，同时都包含格式标识、版本、制作人和导出时间。导入时会重新分配本地 ID，避免覆盖已有记录，并再次执行 schema 校验；批量文件会一次性导入数组中的有效记录。当前 block 模型不依赖外部资源；将来若增加图片或脚本资源，应升级为带资源清单的压缩包格式，而不是直接放宽 JSON。

## 桌面与应用生命周期

“小组件”通过应用商店安装，应用本体采用懒加载。保存后可以单独添加到桌面，桌面布局会沿用现有的版本化布局持久化机制。卸载应用不会删除已保存的小组件数据；用户可以在应用内删除，或在设置的数据管理中清除。

## 验收要点

1. 在应用商店安装“小组件”，输入一句话，确认顶部预览即时出现并按尺寸排布。
2. 继续发送一轮修改（尺寸、颜色、标题或制作人），确认聊天记录和预览同步更新。
3. 点击图片按钮附加参考图，确认缩略图显示在下一条消息上。
4. 保存后刷新页面，确认自制组件、制作人和桌面挂载仍在；系统内置组件可展开查看。
5. 在应用内导出全部或单个记录，确认文件包含格式标识、版本和制作人；导入后生成新 ID，批量文件应导入多个有效记录。
6. 在系统备份/恢复和用户数据清理中确认“小组件”被单独列出。
